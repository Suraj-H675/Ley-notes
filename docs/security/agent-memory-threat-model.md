# Agent memory threat model

Status: focused native continuity with approved capture, transactional native artifact/session/learning/approved-source authority, canonical Brief/Search/Evidence plus opt-in Checkpoint MCP, Specification-only bootstrap context, read-only Memory Compiler interruption evidence, on-demand local Consolidation Inbox review, structured session capture, Codex/Claude lifecycle adapters, reviewed learnings, and explicit privacy/egress/erasure/export controls. Retained Bootstrap Reference, Context Mount, Knowledge Scope, Policy Bundle, external-connector, fine-grained egress, and historical recovery/utility state is compatibility/privacy ancestry only and does not re-enable the retired agent products.

## Assets

- Ley continuity/evidence state plus user-owned historical Markdown/Canvas copies that migration and erasure must not delete
- Project source, documentation, local Git state, and session evidence
- Capture consent and ignore rules
- User-authored Specification notes and private exact-revision approval pins
- Memory trust, provenance, corrections, and project isolation

## Trust boundaries

1. Explicitly selected legacy Agent Memory vault when an older project still needs migration
2. Explicitly initialized project root
3. Private OS-local project-to-vault binding and Specification-approval registries
4. Local CLI/desktop/MCP process
5. Agent host and its lifecycle adapter
6. Cloud model provider when the user intentionally retrieves context

Repository content, transcripts, tool output, generated summaries, MCP arguments, and imported memory are untrusted data. They are not agent policy or executable instructions.

| Moved legacy migration source is replaced with an unrelated directory | Reconnect validates that the selected directory already contains valid captured memory for the exact project before ingestion or binding mutation. | A historical `passed` Verification is laundered into requirement satisfaction | Approved requirement prose and historical Verification records remain separate channels. | Requirement/method prose is automatically bound to an observed result | Ley has no production `acr_`/`vmd_` identities or criterion/method review route. Requirement and verification-method prose remain literal approved Markdown; observed Verification records retain their own evidence/provenance and any semantic relation must be established by the user/agent from source evidence rather than persisted or inferred by Ley | Approved-source exactness, Verification provenance, MCP tool enumeration, and no-derived-projection regressions |

## Explicit non-claims

- Local storage is not encryption at rest; device/vault encryption is a separate choice.
- When a user intentionally supplies Ley context to a cloud agent, that context is visible to that provider.
- Memory and citations can reduce unsupported guessing; no system can guarantee that an LLM never hallucinates.
