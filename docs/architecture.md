# Ley architecture

## Product boundary

Ley ships one product through two runtimes:

- Tauri desktop is the primary, technically complete runtime. It owns unrestricted user-selected filesystem vaults through a small Rust command surface.
- The web application is an installable PWA. Chromium-family browsers can grant a directory handle for a real folder vault; other browsers receive an explicit IndexedDB compatibility mode.

The public website and workspace share the same Vite build but have separate entry routes. `/` is the website and `/app` is the workspace; Tauri always mounts the workspace.

All surfaces follow the [local storage and data boundaries](privacy-and-storage.md). Application assets may be delivered from the web, while knowledge data remains on-device. Context is shown to a cloud agent only when the user intentionally asks that agent to retrieve it.

## Source boundaries

| Directory            | Responsibility                                                         | May depend on                               |
| -------------------- | ---------------------------------------------------------------------- | ------------------------------------------- |
| `src/core`           | Markdown parsing, links, graph construction, indexes, vault operations | data types and small shared utilities       |
| `src/features`       | Complete user-facing capabilities                                      | core, infrastructure gateways, shared       |
| `src/infrastructure` | Dexie persistence and native/browser filesystem integration            | core parsers/index builders, shared         |
| `src/app`            | Runtime initialization and feature composition                         | all application modules                     |
| `src/shared`         | Product-agnostic components, hooks, state, and utilities               | third-party primitives only                 |
| `src/website`        | Public site                                                            | shared presentation primitives where useful |
| `src-tauri`          | Confined native filesystem operations and desktop packaging            | Rust/Tauri only                             |
| `crates/ley-core`    | Identity, ingestion, graph, retrieval, Context Compiler, sessions, and learning ledger | capability I/O and deterministic parsers    |
| `crates/ley-mcp`     | Fixed-project stdio task-context compilation/retrieval and opt-in session capture | `ley-core`, official Rust MCP SDK            |
| `crates/ley-cli`     | Human/agent command surface and MCP process entry point                 | `ley-core`, `ley-mcp`                        |
| `integrations/`      | Installable Codex and Claude Code MCP/hook/skill packages  | published `ley` CLI contract                 |

Feature-specific hooks are colocated with their feature. Only genuinely reusable hooks belong in `shared/hooks`. Tests for pure domain behavior remain beside the module they verify.

Linux development builds emit the native executable plus `.deb` and `.rpm` packages. AppImage packaging is reserved for an Ubuntu-based release runner because the upstream linuxdeploy GTK plugin assumes a legacy gdk-pixbuf module layout that current Arch Linux no longer ships.

## Agent-memory projection

An initialized repository keeps only portable identity, capture consent, and ignore rules in `.ley/`. A private OS-local registry binds that stable project ID to a filesystem vault. A separate private observation catalog records only canonical roots and recency for initialized projects explicitly opened through Ley; it never scans the device or writes project paths into a vault. Binding resolution claims the stable identity and refuses two simultaneously available roots with a copied `.ley` identity. Approved repository evidence is stored as redacted content-addressed artifacts and immutable manifests beneath `<vault>/.ley/agent-memory/projects/<project-id>/`; no repository path is written into the vault.

Ingestion derives a separate immutable project graph from the same post-redaction source boundary. Files, language symbols, calls, imports, inheritance, implementations, manifest dependencies, and bounded local Git state carry artifact snapshot citations. Direct syntax stays deterministic; v1 deliberately leaves names unresolved across files instead of promoting heuristic matches into facts. Each graph and artifact current pointer is atomically replaced under one shared cross-process lock, and both are verified against immutable snapshots before use. Changed captures also update a bounded private history index over immutable graph/artifact pairs; identical ingestion adds no duplicate. A historical read pins and verifies that exact pair rather than combining an old graph with current evidence.

Read-only retrieval opens that store without creating or changing it, holds a shared project lock while verifying the current artifact and graph against their immutable snapshots, and refuses inconsistent pointers. The MCP server is scoped at process startup to one initialized project and one resolved binding. Tool arguments contain no project or vault selector, so an agent cannot use a running server to enumerate or cross into another project. Search, evidence, graph, session, and learning results are bounded; every serialized result also has a 256 KB hard limit. Project evidence carries relative citations and snapshot times, session resume packs report omitted checkpoints and truncation, and learning packs report trust, provenance, current-snapshot freshness, history, and omission counts. All boundaries label stored text as untrusted and distinguish it from current agent policy.

The Context Compiler sits above retrieval rather than replacing it. `compile_project_context` now task-ranks exact current user-approved Specifications first, then asks the existing fixed-project hybrid search for bounded historical candidates and performs separate premise/state, revision-applicability, and admission passes. Specifications are emitted in a distinct `human-intent` section and consume the same result/token budget before memory. Lexical relevance or a conservative semantic-only similarity signal can nominate memory, but learning trust state, durable conflicts, branch applicability, and explicit high-overlap negation conflicts with approved human intent are adjudicated independently before prompt assembly. Contradictory historical guidance is withheld with the exact Specification IDs; direct captured source evidence remains eligible because a mismatch between desired behavior and observed implementation is useful. `premiseAdjudication` separately reports `no-detected-mismatch`, `obsolete-assumption`, `conflicting-state`, or `uncertain-state` when the task itself overlaps explicit durable invalidation/conflict/divergence state. Explicitly superseded learnings retain their designated replacement learning ID and produce a bounded follow-up handle, but Ley never infers supersession from recency, title similarity, or embedding rank. Session decisions have no typed semantic supersession relation, so a newer decision still does not automatically win. Premise warnings are budgeted ahead of ordinary diagnostics and remain distinct from `evidenceState`. The compiler can abstain with `no-useful-evidence`, reserves diagnostic budget, and reports omission coverage. It still reports `liveSourceChecked: false`; no compiler result, Git beacon, or designated replacement replaces live workspace inspection for consequential edits.

Agent-context egress is a separate Authority Plane gate above local storage. An owner-private OS-local registry assigns `agent-ok`, `confirm-per-use`, `local-model-only`, or `never-send` to the fixed active project and optional narrower Specification/Context Mount scopes. MCP defaults to a `cloud` egress target; a deliberately configured local runtime must opt into `--egress-target local`. That startup label is explicit integration intent, not automatic attestation that a model is physically local. `confirm-per-use` remains fail-closed until Ley has a real local confirmation flow. Project policy gates every agent-facing MCP read/resource/write and is rechecked dynamically. Specification policy is evaluated before opening/scoring the note, and mount plus source-project policy is evaluated before reference memory is searched, so blocked sources cannot steer a derivative pack indirectly. The compiler reports bounded `egressTarget`, `egressCoverage`, and `egressExclusions`; the policy registry itself has no MCP mutation route. Local desktop/CLI knowledge access remains separate from model egress.

Read-only project memory now has a non-ingesting Git revision beacon. Ley compares the captured HEAD/branch with bounded live Git metadata and classifies applicability as `current-lineage`, `ancestor`, `merged`, `divergent`, or `unknown` using commit ancestry rather than timestamps or similarity. A positive ancestor proof from a differently named captured branch is labeled `merged` to mean “known landed in the current line,” not “Git necessarily created a merge commit.” Negative ancestry in a shallow/otherwise unresolved repository stays `unknown`. Task-relevant divergent decisions/revision records are withheld; divergent problem-solving remains available as historical experience with its label. Trusted learnings inherit the latest captured snapshot's applicability as a conservative ceiling, so a learning cannot remain apparently current when that capture is divergent from the checked-out HEAD. `revisionFreshness` also discloses tracked working-tree change count without returning live paths. Git-specific beacon failures fail soft, and live file contents are never read by this check.

User-authored Specifications form a separate Authority Plane boundary rather than another memory kind. The note itself remains ordinary Markdown/YAML in the bound vault. A local desktop action writes portable `ley-type: specification` plus a stable `ley-spec-id`, then records an OS-private project/spec/path/SHA-256 approval pin for that exact complete source. The approval registry contains no Specification body, uses an owner-only locked atomic JSON file, and is outside the erasable Agent Memory namespace. Every authority read uses a no-follow vault-relative path and re-hashes the current source: exact matches are current, changed or missing revisions are withheld until explicit reapproval. `ley_project_specifications` exposes only whole current approved revisions as `human-intent`; MCP cannot approve or revoke them. ADR 0032 integrates current approved Specifications into the Context Compiler with task-conditioned lexical nomination, shared budgeting, explicit authority precedence, and conservative conflict suppression for historical guidance.

Structured session capture appends one immutable JSON event per start, prompt/response observation, checkpoint, finish, or user rename request beneath the same project namespace. A separate project lock serializes session writers. Stable request IDs make retries idempotent, while reused IDs with different retained content fail. Checkpoints replace touched project paths with citations to the current approved artifact snapshot. V1-only ledgers retain `session-v1.json`; a deliberate v2 turn event creates `session-v2.json`, and a bound recovery checkpoint creates `session-v3.json`, without rewriting old events or deleting older projections. Reviewable `session.md` is also derived. Turn bodies are pattern-redacted, individually bounded, and subject to a 1 MiB session budget; Minimal keeps body-free disclosure events. Raw transcripts are never captured automatically.

The first Memory Compiler slice is a deterministic recovery projection over that immutable session ledger. Replay derives each checkpoint's event sequence from its authoritative event envelope without changing the persisted checkpoint payload. `compile_session_memory` returns only prompt/response observations whose sequence is later than the latest checkpoint, labels them as untrusted evidence, distinguishes reviewable/partial/metadata-only/empty recovery states, and applies explicit record/text bounds. It never writes a checkpoint or promotes a claim. A recovery checkpoint may use the pack's session event count as an optimistic guard; the session writer rejects it if newer evidence appeared before append.

The second Memory Compiler slice adds a read-only transition verifier above that recovery window. `verify_memory_transition` requires candidate claims to cite exact current `tev_` records or explicitly defer them, rejects stale event counts and invalid/uncovered evidence, and compares candidates with existing structured session memory for exact duplicates or same-subject changed content. A successful result is only `review-required`; it reports `semanticFaithfulnessProven: false` and `liveSourceChecked: false`. The verifier never writes a checkpoint, changes existing memory, or promotes authority. A separate narrow bound writer now supports exactly one `unresolved` recovery claim: it re-verifies the candidate, requires the exact verifier fingerprint and complete recovery evidence set, derives the checkpoint payload itself, and stores binding provenance in a schema-v3 immutable event. Richer candidate kinds remain review-only until their required typed fields can be supplied without invention.

Project learnings use a separate append-only event ledger. A proposal must cite an existing structured-session record and retains any artifact citations from that record. Learning event schema v2 also persists bounded origin lineage for every new proposal/correction: the cited session record, its captured artifact origins, and, when the cited record is a bound recovery checkpoint, the recovery candidate fingerprint plus the exact `tev_` prompt/response evidence behind it. Corrections union newly resolved origins with prior lineage rather than replacing history. Origin lineage participates in the immutable request fingerprint and is therefore integrity-checked during replay. Legacy v1 events remain readable by reconstructing only the direct origins still present in their stored evidence and explicitly marking that reconstruction as not mechanically resolved.

Origin lineage separates two claims that must not be conflated. `mechanicallyResolved` means Ley resolved every provenance edge represented by retained structured evidence without exceeding the durable source bound; it does not mean Ley knows every causal influence on an agent-authored statement. `causalCompletenessProven` therefore remains false for these derived learnings. Automatic derivation also carries `automaticAuthorityCeiling: review-required`: a user may later confirm a learning as trusted, but that human review neither erases the origin chain nor retroactively proves causal completeness. Broad learning lists, hybrid search, the Context Compiler, and mounted-reference context carry only a compact origin summary; explicit learning inspection exposes the full bounded lineage with a separate 32-source disclosure cap and truthful omission metadata.

Replay derives trust, provenance, confidence, temporal validity, correction history, corroborating-session count, and current-source freshness. Every proposal starts review-required; only a user confirmation creates trusted memory. Agent disputes and source-hash changes return a lesson to the review inbox without erasing its history. Rejection and supersession are terminal, and replacement graphs are checked for missing targets and cycles.

Context Mount authority is stored separately from both project memory and the observation catalog. The private mount registry records only a stable mount ID, active project ID, source project ID, creation time, whether the user explicitly enabled bounded agent context, and—in schema v3—a bounded history of historical mount-ID → source-project-ID pairs for mounts that were agent-enabled; project/vault paths remain owned by the existing catalog/binding registries. `ley mount add/list/remove` is the local authorization surface. Legacy v1 mounts stay agent-disabled until explicitly re-added, while existing schema-v2 agent-enabled mounts are migrated into mount history before the next mutation. Unmount removes current reference authority but intentionally does not erase that mount/source relation, because later mount-specific or source-project egress restrictions may still need to constrain historical derivatives in the active project. `ley_compile_context` may resolve only currently agent-enabled mounts for direct reference use while holding the mount lock, revalidate source identity/binding, and search already-captured source memory. Specifications and active-project context are assembled first; mounted references use only the remaining shared result/token budget, retain mount/source provenance and an `untrusted-mounted-project-memory` boundary, and never change the active project/session write scope. Missing, identity-changed, unbound, or unavailable captured sources fail closed and remain diagnostic.

Agent-context egress is enforced before host/model return. Project policy is a whole-scope ceiling; Specification policy is checked before the approved note is opened or task-scored; mount and source-project policy are checked before reference search. Restrictive Specification/mount overrides remain OS-private authority even if the currently approved/mounted scope later disappears, until the local user deliberately resets that retained stable ID to `agent-ok`. Because ordinary session/decision/problem records and many learnings cannot yet prove complete causal independence from every finer-grained source that may have influenced them, Ley uses a conservative non-laundering fallback: whenever a Specification, mount, or historically agent-enabled source is blocked for the configured target, the agent-facing compiler withholds session/decision/problem/learning candidates whose source independence is unproven. Direct captured revision/artifact/symbol/dependency evidence remains governed by the active project's own policy. `egressCoverage.historicalMemoryWithheld` and `withheldDerivedResults` disclose that ceiling. Broad historical MCP readers apply the same fail-closed rule rather than allowing a blocked source to be recovered through old session or learning text.

Topic Dossiers are the first P1 derived-intelligence view. `compile_topic_dossier` / `ley_topic_dossier` build an on-demand, non-persistent topic projection over the same fixed-project captured evidence and structured memory. The dossier preserves stable evidence IDs/citations, current trusted learning roles, conflicts, revision applicability, important artifacts, supporting sessions, open tasks/problems/unresolved items, and recent verification. Session/revision search rows are treated as secondary under budget pressure because supporting-session identity and top-level revision freshness already represent those dimensions. The projection is source-fingerprinted, strictly token-bounded, reports truthful omissions, keeps `liveSourceChecked: false`, and writes no dossier cache. It uses the same historical-memory egress gate as broad session/learning readers, so a restricted source cannot be laundered through topic consolidation. Dossiers are navigation/progressive-disclosure views, never authority and never a substitute for task-specific Context Compiler admission.

Current Project State is the next P1 derived-intelligence view. `current_project_state` / `ley_project_state` build an on-demand, non-persistent project-status projection over the fixed project's captured snapshot, structured sessions, reviewed learnings, and revision metadata. Working state comes only from active/paused sessions and their latest checkpoint; open tasks/problems/unresolved items are drawn only from that bounded continuation state. Recent decisions and verification may be returned for orientation, but decisions are explicitly labeled `historical-project-memory` with `currentStateProven: false` so recency cannot silently become authority. Reviewed current-trusted learnings are separated from review-required, contested, stale, and source-changed knowledge. The projection carries `revisionFreshness`, a deterministic state fingerprint, truthful coverage/omission counts, `liveSourceChecked: false`, and no persisted state cache. It uses the same historical-memory egress gate as resume/dossiers/session/learning readers.

Context Pack Inspector is the third P1 derived-intelligence view. Every finalized compiled context pack now carries a logical `contextPackId` plus `createdAtUnixMs`. The ID is computed only after Specifications, active-project admission, mounted references, premise/revision diagnostics, and agent-egress filtering are finalized, and excludes the creation timestamp so unchanged logical pack content can be reproduced. `ley_context_pack_inspect` recompiles through the same agent-aware compiler path and returns a text-light manifest: stable IDs/citations, authority/admission and inclusion reasons, exclusions including egress, conflicts/premise warnings/gaps, retrieval and revision signals, budget composition, coverage/omissions, mount scopes, and follow-up handles. It deliberately omits included source/specification/excerpt bodies and persists no historical pack. If an expected pack ID no longer matches, the Inspector reports that mismatch and refuses to claim it reconstructed the older pack. The original compile call owns `createdAtUnixMs`; Inspector reports `recompiledAtUnixMs` for the current reconstruction.

The desktop Agent Memory workspace is a thin Tauri adapter over these shared core projections. Its first level is a bounded, recent-first Projects hub derived only from the private observation catalog. Each card revalidates the live project identity and independently reports ready, unbound, uncaptured, missing-project, moved-vault, identity-change, or memory-error state; ready summaries read counts only from that project's resolved vault, and exact session-state totals stream over records without retaining every session projection. A separate bounded cross-project search independently revalidates every observed project and searches sessions, decisions, problems/outcomes, lessons, captured files, symbols, and dependencies through captured projections; unavailable scopes are counted and skipped, results remain cited and untrusted, and the worker never scans for or silently captures projects. Opening a project leads to its overview, Sessions, Decisions, Problems & Outcomes, Lessons, Specifications, Artifacts, graph, and Review surfaces. Initialization uses Structured capture, binding uses the private registry, and refresh runs deterministic ingestion. The graph can reopen any indexed immutable capture, applies type/relationship/provenance filters in the shared engine before bounding, and reads a selected node or edge citation only from that capture's matching immutable artifact. Session/activity evidence navigation uses a separate snapshot-pinned read: the engine requires the recorded artifact snapshot, path, content hash, and bounded line range, rejects mismatched hashes, and never falls back to the live working tree. Minimal captures report that source was not retained. The overview consumes a token-bounded resume pack, while Sessions reads a separate complete lightweight index so a bounded context pack is never mislabeled as full history. Opening a session replays a bounded context projection with checkpoint decisions, tasks, problem attempts/outcomes, structured resolutions, commands, verification, handoff, snapshot-pinned artifacts, and the newest naming revisions; original names and omission counts remain visible. Cited artifact controls open the exact historical excerpt beside its captured graph context, while learning evidence links to its complete originating session and artifact inventory. The user can append a reasoned rename even after completion without changing session identity. The learning provenance inspector shows temporal validity and immutable history. Its correction editor preserves the complete authoritative evidence set, appends a user-authored version, and resets trust; correction and review actions carry the inspected event count so a concurrent event fails stale instead of approving unseen text. Separate explicit note-link paths copy either a fully visible current trusted lesson or an inspected bounded session handoff into ordinary Markdown with portable provenance. Before either action, the native adapter canonically matches the open notes vault to the project's private binding; cross-vault writes fail without exposing machine paths. Linked notes enter the normal vault/index/navigation path while their source ledgers remain immutable and independent; stable learning or project/session IDs prevent duplicate promotion after note renames or moves. The PWA renders an explicit capability boundary because browser vaults cannot expose the OS-private catalogs or stdio MCP process.

Capture & privacy settings are loaded only when their project surface opens. The shared engine serializes privacy writers with a project-specific lock in Ley's private OS configuration, revalidates project identity and the expected current mode under that lock, and atomically changes the repository-local evidence policy. It preserves custom roots/ignore/limit fields and requires explicit consent before enabling raw-evidence permission. The native adapter then re-ingests through the existing bound vault and returns a refreshed dashboard. Minimal omits current source blobs; Structured retains redacted source; Full Evidence also permits compatible adapters to submit raw host evidence but does not make Ley capture transcripts automatically.

Whole-project Agent Memory erasure uses a distinct lifecycle lock stored beside, rather than inside, the erasable project namespace. Every artifact/graph, session, and learning store holds that lock shared for the duration of an operation; deletion holds it exclusively, revalidates the project-relative no-follow directory, and removes the complete namespace. Project source, ordinary vault content, `.ley` metadata, binding, observation, and the content-free lifecycle lock remain. The resulting inspection state is **Needs capture**. This is logical local deletion and makes no forensic-wipe claim.

MCP session writes are absent by default. `--allow-session-writes` enables start, generic checkpoint, finish, and the narrow bound unresolved-recovery commit route at process construction, so an existing read-only configuration cannot gain authority from a tool argument or stored instruction. Write tools return compact receipts and delegate to the same session engine as the CLI.

MCP learning proposals use an independent startup capability. `--allow-learning-proposals` adds one route that hardcodes agent authority and produces only tentative, review-required records. Confirmation, correction, rejection, supersession, deletion, and promotion remain absent. Default lesson listing includes only user-trusted records whose artifact citations still match the latest captured snapshot; explicit review/all scopes remain visibly untrusted.

The lifecycle adapter is a separate stdout-clean CLI surface. `ley hook --host ...` accepts the current host's documented JSON event, ignores transcript paths, and maps the host/session pair to a deterministic project-scoped Ley session. Agent-facing hooks use the same OS-private egress authority as MCP: the default target is `cloud`, and `--egress-target local` is an explicit integration assertion rather than runtime attestation. A project-level denial produces a host-valid no-op without creating/capturing a Ley session. When a finer-grained source blocks historical egress, SessionStart may establish only the stable Ley session identity and injects a content-free egress-withheld notice; it does not read or inject the resume pack, reviewed learnings, or recovery state. When allowed, startup uses the existing bounded resume projection; turn hooks append distinct prompt/response evidence according to capture policy. These bodies never enter startup context. If the same resumed session has post-checkpoint observations, startup injects only a bounded recovery count/state signal; explicit `ley_session_memory_compile` inspection followed by `ley_session_memory_verify` is required before reconstructing evidence-derived structure. Uninitialized and unbound working directories are explicit no-ops, and payload paths never select the project. In those workspaces the packaged MCP command serves a protocol-valid zero-capability connection with no tools or resources. Rich structured memory still comes from typed MCP checkpoints rather than transcript inference.

Project resume context composes these existing stores without creating a new authority layer. It prioritizes active and paused sessions before recent history, projects only the newest checkpoint and handoff details needed to continue, and includes only verified/trusted/current artifact-backed lessons. Stable IDs link every compact item back to the bounded session, learning, graph, or artifact readers. Both CLI and MCP use the same projection and budget rules.

## Persistence contract

For filesystem vaults, Markdown is authoritative. A vault scan projects files into Dexie, then rebuilds links and tags after every page exists so forward references resolve correctly. First scans derive IDs from vault identity and relative path; subsequent scans preserve the current ID for each matching path so in-session creations, renames, tabs, and revisions remain coherent.

The active `pages`, `assets`, and `revisions` tables represent exactly one vault at a time. Before a browser-local vault yields the active projection to a filesystem folder, Ley snapshots its authoritative pages, binary assets, and revision history into dedicated browser-local tables. Returning restores that snapshot and rebuilds disposable links/tags. Filesystem rescans preserve existing IDs by path for the same vault, while changing vaults clears cache-only assets and history so state cannot leak across vault boundaries.

Writes follow this order:

1. Serialize YAML properties and Markdown body.
2. Persist the file through the active vault adapter. Desktop writes stage and atomically rename a temporary file.
3. Update the local page projection.
4. Rebuild backlinks, tags, search, and graph-derived state.

Editor content writes are serialized per note. A rapid later save cannot be overtaken by an earlier filesystem/index rebuild, and leaving an editor flushes its pending debounced value before teardown. This keeps authoritative Markdown and every derived row on the same newest revision.

Cell-level property mutations also join the per-note mutation queue and merge against the newest projected frontmatter inside that queue. Two collection cells, the properties panel, and an editor autosave therefore cannot overwrite one another with stale object snapshots.

Renames move the file and retarget incoming wiki links. Ordinary relative Markdown links are resolved by vault path, indexed as backlinks and graph edges, and rewritten when either their source or target moves so their filesystem meaning remains stable. Folder moves preserve note identity and titles, so links and note bookmarks remain valid; duplicates receive an independent title/path and intentionally drop aliases to avoid ambiguous resolution. Deletes move filesystem notes into `.trash`; browser-local notes use a recoverable soft-delete marker and expose restore/permanent-delete controls. Binary attachments live under `attachments/` and are constrained by extension, size, and safe relative paths. Interoperable JSON Canvas documents live under `canvases/` and use the same atomic-write and trash lifecycle. Ley normalizes all JSON Canvas 1.0 text, file, link, and group nodes plus file subpaths, group background metadata, colors, edge sides, endpoint styles, and labels; malformed geometry and dangling edges are excluded before rendering or saving. Spatial edge paths are derived from document coordinates so resize, pan, zoom, reload, and cross-app imports do not depend on transient renderer measurements. All native relative paths reject absolute paths and traversal segments.

Workspace metadata is namespaced by the active vault identity. Desktop vaults use their full path, browser-local uses a dedicated identity, and browser directory handles receive a persisted random ID rather than relying on a potentially colliding folder name. Note bookmarks, destination bookmarks, saved searches, named workspace layouts, and navigation sessions therefore never cross vault boundaries. Saved searches are validated setting records rather than hidden note files, because they describe Ley workspace retrieval rather than user-authored knowledge. Their optional collection configuration contains presentation-only column IDs and sort direction; every displayed value is still read from Markdown/YAML. Heading and block bookmarks resolve a note by stable page ID and then path; heading text and explicit `^block-id` anchors provide the durable in-note destination. Creating a block bookmark writes that portable identity into authoritative Markdown instead of storing a fragile line offset. Missing-note bookmarks remain visible and recover automatically if the note returns. Navigation sessions store both stable page IDs and paths, restore tab order, primary and secondary panes, focused pane, and recents, and discard references to deleted or unavailable notes. Named layouts reuse that resilient note-reference contract and add presentation-only sidebar visibility, right-dock context, and split width; loading drops missing notes and refuses to replace the live arrangement when every reference is stale. Editor insert/jump events carry their page identity, and link opens carry their source pane, so two mounted editors cannot receive one another's commands.

The desktop runtime owns one recursive native watcher for the active vault. It emits only visible Markdown and JSON Canvas paths, ignores hidden/internal files, and suppresses events caused by Ley's own atomic writes. The web layer debounces event bursts before rescanning and reconciles tabs against the new projection. If an external edit arrives while the current CodeMirror document is dirty, autosave pauses and the user explicitly chooses the disk version or their local version; neither side wins silently.

## Derived state

Dexie tables for pages, blocks, links, tags, and settings support reactive UI queries. FlexSearch and the synchronous title resolver subscribe to Dexie and are disposable. CodeMirror's shared completion lifecycle reads the derived tag table on demand, so tag authoring reuses the current vault taxonomy without making the index authoritative. The search projection indexes title, aliases, content, tags, paths, and flattened YAML properties; structured operators are parsed separately and applied as composable post-filters so filter-only queries and exclusions remain exact. Collection tables reuse the same parsed filters against a live page/tag snapshot, discover columns from frontmatter coverage, and never persist row data outside the notes. Revisions are sparse checkpoints rather than keystroke logs and are restored through the same normal save path.

## Design system

Ley uses self-hosted Geist Sans and Geist Mono with semantic CSS tokens. Radix primitives provide accessible interaction foundations where native controls are insufficient. Feature components consume shared buttons, inputs, keyboard hints, and tokens rather than hard-coded brand values.

## Non-goals

- A proprietary document format
- Mandatory cloud accounts or sync
- Treating the graph as the primary editor
- Claiming browser-local storage is equivalent to a filesystem vault
- A plugin API before the core file format and lifecycle are stable
