# Ley architecture

## Product boundary

Ley ships one product through two runtimes:

- Tauri desktop is the primary, technically complete runtime. It owns unrestricted user-selected filesystem vaults through a small Rust command surface.
- The web application is an installable PWA. Chromium-family browsers can grant a directory handle for a real folder vault; other browsers receive an explicit IndexedDB compatibility mode.

The public website and workspace share the same Vite build but have separate entry routes. `/` is the website and `/app` is the workspace; Tauri always mounts the workspace.

All surfaces follow the [local storage and data boundaries](privacy-and-storage.md). Application assets may be delivered from the web, while knowledge data remains on-device. Context is shown to a cloud agent only when the user intentionally asks that agent to retrieve it.

## Source boundaries

| Directory            | Responsibility                                                         | May depend on                               |
| -------------------- | ---------------------------------------------------------------------- | ------------------------------------------- |
| `src/core`           | Markdown parsing, links, graph construction, indexes, vault operations | data types and small shared utilities       |
| `src/features`       | Complete user-facing capabilities                                      | core, infrastructure gateways, shared       |
| `src/infrastructure` | Dexie persistence and native/browser filesystem integration            | core parsers/index builders, shared         |
| `src/app`            | Runtime initialization and feature composition                         | all application modules                     |
| `src/shared`         | Product-agnostic components, hooks, state, and utilities               | third-party primitives only                 |
| `src/website`        | Public site                                                            | shared presentation primitives where useful |
| `src-tauri`          | Confined native filesystem operations and desktop packaging            | Rust/Tauri only                             |
| `crates/ley-core`    | Identity, ingestion, graph, retrieval, Context Compiler, sessions, and learning ledger | capability I/O and deterministic parsers    |
| `crates/ley-mcp`     | Fixed-project stdio context/retrieval plus the single-tool uninitialized-workspace Bootstrap context server | `ley-core`, official Rust MCP SDK            |
| `crates/ley-cli`     | Human/agent command surface and MCP process entry point                 | `ley-core`, `ley-mcp`                        |
| `integrations/`      | Installable Codex and Claude Code MCP/hook/skill packages  | published `ley` CLI contract                 |

Feature-specific hooks are colocated with their feature. Only genuinely reusable hooks belong in `shared/hooks`. Tests for pure domain behavior remain beside the module they verify.

Linux development builds emit the native executable plus `.deb` and `.rpm` packages. AppImage packaging is reserved for an Ubuntu-based release runner because the upstream linuxdeploy GTK plugin assumes a legacy gdk-pixbuf module layout that current Arch Linux no longer ships.

## Agent-memory projection

An initialized repository keeps only portable identity, capture consent, and ignore rules in `.ley/`. A private OS-local registry binds that stable project ID to a filesystem vault. A separate private observation catalog records only canonical roots and recency for initialized projects explicitly opened through Ley; it never scans the device or writes project paths into a vault. Binding resolution claims the stable identity and refuses two simultaneously available roots with a copied `.ley` identity. Approved repository evidence is stored as redacted content-addressed artifacts and immutable manifests beneath `<vault>/.ley/agent-memory/projects/<project-id>/`; no repository path is written into the vault.

Ingestion derives a separate immutable project graph from the same post-redaction source boundary. Files, language symbols, calls, imports, inheritance, implementations, manifest dependencies, and bounded local Git state carry artifact snapshot citations. Direct syntax stays deterministic. Cross-file symbol names remain deliberately unresolved rather than promoting heuristic name matches into facts, while an unambiguous relative JavaScript/TypeScript import may resolve to the exact captured `File` node using only the approved captured path set; package imports, ambiguous matches, and project-escape attempts remain external/unresolved. Each graph and artifact current pointer is atomically replaced under one shared cross-process lock, and both are verified against immutable snapshots before use. Graph extraction semantics are rebuildable: `ley ingest` reconstructs the graph even when artifact identity is unchanged, so richer derived relations create a new graph snapshot without rewriting immutable historical graph snapshots. Changed captures also update a bounded private history index over immutable graph/artifact pairs; identical graph identity adds no duplicate. A historical read pins and verifies that exact pair rather than combining an old graph with current evidence.

Read-only retrieval opens that store without creating or changing it, holds a shared project lock while verifying the current artifact and graph against their immutable snapshots, and refuses inconsistent pointers. The normal MCP server is scoped at process startup to one initialized project and one resolved binding. Tool arguments contain no project or vault selector, so an agent cannot use a running server to enumerate or cross into another project. Search, evidence, graph, session, and learning results are bounded; every serialized result also has a 256 KB hard limit. Project evidence carries relative citations and snapshot times, session resume packs report omitted checkpoints and truncation, and learning packs report trust, provenance, current-snapshot freshness, history, and omission counts. All boundaries label stored text as untrusted and distinguish it from current agent policy. ADRs 0058/0059 add one deliberately separate uninitialized-workspace MCP mode: a workspace with explicit Bootstrap Specification and/or Bootstrap Reference authority can start it, and that server advertises exactly read-only `ley_compile_context` with no resources or target project-memory/session/write tools.

The Context Compiler sits above retrieval rather than replacing it. `compile_project_context` now task-ranks exact current user-approved Specifications first, then asks the existing fixed-project hybrid search for bounded historical candidates and performs separate premise/state, revision-applicability, and admission passes. Specifications are emitted in a distinct `human-intent` section and consume the same result/token budget before memory. Lexical relevance or a conservative semantic-only similarity signal can nominate memory, but learning trust state, durable conflicts, branch applicability, and explicit high-overlap negation conflicts with approved human intent are adjudicated independently before prompt assembly. Contradictory historical guidance is withheld with the exact Specification IDs; direct captured source evidence remains eligible because a mismatch between desired behavior and observed implementation is useful. `premiseAdjudication` separately reports `no-detected-mismatch`, `obsolete-assumption`, `conflicting-state`, or `uncertain-state` when the task itself overlaps explicit durable invalidation/conflict/divergence state. Explicitly superseded learnings retain their designated replacement learning ID and produce a bounded follow-up handle, but Ley never infers supersession from recency, title similarity, or embedding rank. Session decisions have no typed semantic supersession relation, so a newer decision still does not automatically win. Premise warnings are budgeted ahead of ordinary diagnostics and remain distinct from `evidenceState`. The compiler can abstain with `no-useful-evidence`, reserves diagnostic budget, and reports omission coverage. It still reports `liveSourceChecked: false`; no compiler result, Git beacon, or designated replacement replaces live workspace inspection for consequential edits.

Agent-context egress is a separate Authority Plane gate above local storage. An owner-private OS-local registry assigns `agent-ok`, `confirm-per-use`, `local-model-only`, or `never-send` to the fixed active project and optional narrower Specification/Context Mount/external-connector scopes. MCP defaults to a `cloud` egress target; a deliberately configured local runtime must opt into `--egress-target local`. That startup label is explicit integration intent, not automatic attestation that a model is physically local. `confirm-per-use` remains fail-closed until Ley has a real local confirmation flow. Project policy gates every agent-facing MCP read/resource/write and is rechecked dynamically. Specification policy is evaluated before opening/scoring the note, mount plus source-project policy is evaluated before reference memory is searched, and connector policy is evaluated before connector metadata/snapshots can be returned, so blocked sources cannot steer or leak through agent context indirectly. The compiler reports bounded `egressTarget`, `egressCoverage`, and `egressExclusions`, including `blockedExternalConnectors`; the policy registry itself has no MCP mutation route. Local desktop/CLI knowledge access remains separate from model egress.

Read-only project memory now has a non-ingesting Git revision beacon. Ley compares the captured HEAD/branch with bounded live Git metadata and classifies applicability as `current-lineage`, `ancestor`, `merged`, `divergent`, or `unknown` using commit ancestry rather than timestamps or similarity. A positive ancestor proof from a differently named captured branch is labeled `merged` to mean “known landed in the current line,” not “Git necessarily created a merge commit.” Negative ancestry in a shallow/otherwise unresolved repository stays `unknown`. Task-relevant divergent decisions/revision records are withheld; divergent problem-solving remains available as historical experience with its label. Trusted learnings inherit the latest captured snapshot's applicability as a conservative ceiling, so a learning cannot remain apparently current when that capture is divergent from the checked-out HEAD. `revisionFreshness` also discloses tracked working-tree change count without returning live paths. Git-specific beacon failures fail soft, and live file contents are never read by this check.

User-authored Specifications form a separate Authority Plane boundary rather than another memory kind. The note itself remains ordinary Markdown/YAML in the bound vault. A local desktop action writes portable `ley-type: specification` plus a stable `ley-spec-id`, then records an OS-private project/spec/path/SHA-256 approval pin for that exact complete source. The approval registry contains no Specification body, uses an owner-only locked atomic JSON file, and is outside the erasable Agent Memory namespace. Every authority read uses a no-follow vault-relative path and re-hashes the current source: exact matches are current, changed or missing revisions are withheld until explicit reapproval. `ley_project_specifications` exposes only whole current approved revisions as `human-intent`; MCP cannot approve or revoke them. ADR 0032 integrates current approved Specifications into the Context Compiler with task-conditioned lexical nomination, shared budgeting, explicit authority precedence, and conservative conflict suppression for historical guidance. ADR 0068 adds a read-only `acceptanceCriteria` projection over one unambiguous explicit `Acceptance criteria` ATX section in that exact approved revision. Criteria keep exact raw Markdown slices, revision-bound deterministic IDs, and source line ranges; checkbox/task-list syntax is preserved literally and never interpreted as completion or verification state. ADR 0071 adds the parallel read-only `verificationMethods` projection for one unambiguous explicit `Verification method`/plural section. Methods carry revision-bound `vmd_` IDs and exact slices/ranges but explicitly prove no criterion binding, observed-result binding, execution, status, or outcome. Both projections are rebuilt from the approved source, are never persisted independently, obey the parent Specification's egress/staleness boundary, and may use only spare output budget; Acceptance criteria retain priority over Verification methods. ADR 0070 provides `ley_acceptance_criterion_verification_review` for one caller-supplied exact current criterion and one exact historical session Verification record. ADR 0072 extends that same tool with an optional exact current `vmd_`, allowing a caller-supplied `acr_ -> vmd_ -> ver_` review without another MCP tool. Ley revalidates all supplied handles, uses a separate method-aware fingerprint domain, and still leaves method execution/outcome, criterion satisfaction, semantic coverage, current implementation state, and live-source correctness unproven. The review persists no relation and a historical `passed` status never becomes acceptance state.

Bootstrap authority extends reviewed human intent and explicitly selected captured reference evidence to an uninitialized target without inventing a target `prj_` identity. The owner-private `bootstrap-specifications-v1.json` registry is schema v2 but keeps its filename for compatibility: each canonical target directory **generation** may contain exact `bsg_` Specification pins and lower-authority `brg_` source-project reference grants. On supported Unix filesystems the generation combines device/inode with filesystem creation time; unsupported generation semantics fail closed while normal project initialization remains available. The registry stores no Specification/reference body and agent-facing output contains no machine paths. Compilation serializes target transition → bootstrap authority → egress snapshot → current source binding. Specifications additionally verify exact approved hashes; reference reads check source-project egress before searching already-captured memory and revalidate the exact expected source project ID before/after that search so a pathname replacement cannot substitute another project. The combined MCP compiler spends budget on whole Specifications first, then applies the normal memory admission rules to reference evidence. It never enumerates unattached projects or reads live source file contents; bounded live Git metadata may only inform freshness. Reference-only workspaces do not receive lifecycle-hook injection. Initialization retires the entire Specification/reference authority record atomically before establishing writable `.ley` identity and restores it on failed setup. ADR 0058 defines Specification semantics; ADR 0059 defines captured reference-project bootstrap.

Structured session capture appends one immutable JSON event per start, prompt/response observation, supported host-tool observation, checkpoint, finish, or user rename request beneath the same project namespace. A separate project lock serializes session writers. Stable request IDs make retries idempotent, while reused IDs with different retained content fail. Checkpoints replace touched project paths with citations to the current approved artifact snapshot. Durable session event/projection versions are additive: ordinary lifecycle events remain v1; bounded turn evidence uses v2; candidate-bound unresolved recovery checkpoints use v3; verification evidence links use v4; context-utility events use v5; multimodal-citation checkpoints use v6; explicitly imported historical host turns use v7; candidate-bound typed Decision/Problem recovery checkpoints use v8; verifier-bound typed Task recovery checkpoints use v9; verifier-bound typed Plan recovery checkpoints use v10; atomic multi-claim recovery checkpoints with record-specific evidence bindings use v11; verifier-bound rich Problem recovery checkpoints with per-Problem/Attempt/Resolution evidence bindings use v12; atomic rich-Problem composite recovery checkpoints use v13; and deterministic supported host-tool observations use v14. Older events/projections are not rewritten merely because a newer event kind exists. Reviewable `session.md` is also derived. Prompt/response and retained supported-tool bodies are pattern-redacted, individually bounded, and share one 1 MiB automatic-evidence session budget; supported Bash hook input additionally has fail-closed pre-normalization text, structured-node/fan-out, and nesting-depth bounds so structured flattening cannot traverse/sort/allocate without limit before retention. Minimal keeps body-free disclosure events. Raw transcripts are never captured automatically.

Historical host import is deliberately separate from lifecycle capture. The first slice accepts only an explicitly supplied regular/no-follow file containing Codex's documented global message-history JSONL shape (`session_id`, Unix-second `ts`, `text`) plus one explicitly selected host session UUID. Ley never discovers the Codex home directory, never follows a supplied symlink, and does not parse richer Codex rollout/session transcripts. The import path is locally bounded to 64 MiB / 100,000 JSONL records / 1 MiB per record / 512 selected messages, creates one completed `SessionSourceKind::Import` Ley session, stores only an opaque `hsi_` source reference, and applies the active project's ordinary turn redaction/capture policy. Structured/Full Evidence may retain the bounded redacted selected user-message bodies; Minimal records body-free imported observations. No assistant response, tool activity, hidden reasoning, raw source path, or raw host UUID is manufactured or retained. Imported turns preserve their source timestamps and use the `untrusted-imported-host-history` boundary. Exact retries replay; a changed selected-message snapshot creates a new immutable Ley session with the same opaque source identity. Imported sessions are excluded from automatic Resume and from Memory Health's unconsolidated-evidence nag; explicit session inspection, Memory Compiler, and project search remain available, with search time based on the historical source timestamp rather than import time. ADR 0054 defines this slice.

The first Memory Compiler slice is a deterministic recovery projection over that immutable session ledger. Replay derives each checkpoint's event sequence from its authoritative event envelope without changing the persisted checkpoint payload. `compile_session_memory` returns candidate-bound prompt/response observations whose sequence is later than the latest checkpoint, labels them as untrusted evidence, distinguishes reviewable/partial/metadata-only/empty recovery states, and applies explicit record/text bounds. ADR 0066 additionally exposes post-checkpoint supported Bash observations through a separate `supportingToolEvidence` collection. Those `toe_` records are supporting provenance only: they do not change `totalUnconsolidatedEvidence` or recovery state, cannot be cited by the current candidate-bound writers, and a normal `PostToolUse` return is not proof of command/test success. ADR 0067 adds a deterministic read-only `automaticCommandCandidates` projection when a retained Bash command is complete. Each candidate points back to the exact `toe_` row, uses explicit `exitCode: null`, and proves no command/test/Verification outcome; incomplete, omitted, or command-truncated observations disclose why they are ineligible. ADR 0069 gives that projection a source-bound deterministic fingerprint plus a separate read-only observed-Command verifier that re-checks the exact `toe_` source, current event count, checkpoint boundary, retention, and truncation. A `review-required` result still grants no persistence/write authority and proves no outcome. `toe_` remains outside every existing recovery-writer evidence namespace; a durable Command writer is deferred until mixed turn/tool recovery can advance the checkpoint boundary atomically without stranding unconsolidated `tev_` evidence. Tool events still advance the immutable session event count, so any later session event stales an earlier observed-Command verification or bound recovery write. The compiler/verifier never writes a checkpoint or promotes a claim. A recovery checkpoint may use the pack's session event count as an optimistic guard; the session writer rejects it if newer evidence appeared before append.

The second Memory Compiler slice adds read-only transition verification above that recovery window. `verify_memory_transition` requires candidate claims to cite exact current `tev_` records or explicitly defer them, rejects stale event counts and invalid/uncovered evidence, and compares candidates with existing structured session memory for exact duplicates or same-subject changed content. A successful result is only `review-required`; it reports `semanticFaithfulnessProven: false` and `liveSourceChecked: false`. Verification never writes a checkpoint, changes existing memory, or promotes authority. Candidate-bound writers support exactly one `unresolved` claim through schema v3, exactly one lossless minimal `decision`/`problem` claim through schema v8, one typed Task through schema v9, and one typed Plan through schema v10. ADR 0063 adds a separate atomic batch verifier/writer for 2–50 already-supported unresolved/Decision/Problem/Task/Plan candidates that share one recovery window. Its batch fingerprint binds the explicit checkpoint summary, canonical typed candidate set, exact event count, and complete current evidence accounting; schema v11 appends the whole verified set as one checkpoint while persisting both the complete evidence union and exact per-child evidence subsets. ADR 0064 adds a separate typed rich-Problem verifier/writer for one new debugging episode containing exact expected behavior, ordered Attempts with outcomes/evidence, and an optional structured Resolution. Schema v12 preserves one evidence binding for the Problem, each Attempt, and the Resolution, re-verifies the full rich candidate under the writer lock, and never mutates an older same-title Problem. ADR 0065 adds a third separate recovery family for one rich Problem plus 1–49 existing minimal siblings from the same evidence window, bounded to at most 50 verifier components across the rich parent, ordered Attempts, optional Resolution, and sibling set. Its `ley-memory-transition-v5-composite` fingerprint and schema-v13 writer preserve the rich episode plus sibling state atomically without changing v11 or v12 meaning, and persist both the complete recovery evidence union and exact evidence binding for every durable child. Exact committed retries replay before the now-closed recovery window must be re-opened. Every bound writer requires the exact verifier fingerprint and complete recovery evidence set, derives the checkpoint payload inside Ley, and persists binding provenance. Standalone Attempt/Resolution updates, Command, Verification, and Summary remain review-only until their temporal/parent semantics can be supplied without invention. ADR 0060 defines the minimal Decision/Problem extension; ADR 0061 defines typed Task recovery; ADR 0062 defines typed Plan recovery; ADR 0063 defines atomic multi-claim recovery; ADR 0064 defines typed rich-Problem recovery; ADR 0065 defines atomic rich-Problem composite recovery; ADR 0066 defines deterministic supporting host-tool evidence without broadening the recovery-writer authority surface.

The third Memory Compiler slice is an on-demand **Consolidation Inbox** over meaningful native-session lifecycle boundaries. `consolidation_inbox` considers only paused, completed, and abandoned non-import sessions, compiles their retained post-checkpoint evidence deterministically, and returns stable session/turn IDs plus bounded counts and advisory actions. It excludes active and imported sessions, never returns turn bodies or machine paths, invokes no model, starts no background work, persists nothing, and cannot mutate the cited session. Each item keeps `semanticFaithfulnessProven: false` and `automaticWriteAllowed: false`. When captured turn bodies exist, the exact retained `tev_` prompt/response IDs may be used by the separate learning-proposal workflow; that proposal still starts tentative/review-required and does not mark the inbox evidence consumed. ADR 0055 defines this slice.

Project learnings use a separate append-only event ledger. A proposal must cite retained Ley session evidence: either an existing structured-session record or a captured body-bearing `tev_` user-prompt/assistant-response record. Body-free turn observations cannot support a proposal. Structured-record evidence retains its artifact citations; direct turn evidence retains exact session/record lineage. Learning event schema v2 also persists bounded origin lineage for every new proposal/correction: the cited session record or direct turn evidence, its mechanically known captured artifact origins when applicable, and, when the cited record is a bound recovery checkpoint, the recovery candidate fingerprint plus the exact `tev_` prompt/response evidence behind it. For schema-v11 atomic recovery, the checkpoint record resolves to the complete batch union while a cited Decision/Problem/Task/Plan child or read-projected `unr_...` unresolved child resolves only to that child's persisted evidence subset. For schema-v12 rich-Problem recovery, a cited Problem, Attempt, or Resolution likewise resolves only its own persisted recovery-evidence subset while retaining the overall rich-Problem candidate fingerprint. Schema-v13 composite recovery keeps the same separation across both families: citing the checkpoint resolves the complete composite evidence union, while a rich Problem/Attempt/Resolution or minimal sibling child resolves only its own record-specific evidence subset while retaining the one composite candidate fingerprint. Corrections union newly resolved origins with prior lineage rather than replacing history. Origin lineage participates in the immutable request fingerprint and is therefore integrity-checked during replay. Legacy v1 events remain readable by reconstructing only the direct origins still present in their stored evidence and explicitly marking that reconstruction as not mechanically resolved.

Origin lineage separates two claims that must not be conflated. `mechanicallyResolved` means Ley resolved every provenance edge represented by retained structured evidence without exceeding the durable source bound; it does not mean Ley knows every causal influence on an agent-authored statement. `causalCompletenessProven` therefore remains false for these derived learnings. Automatic derivation also carries `automaticAuthorityCeiling: review-required`: a user may later confirm a learning as trusted, but that human review neither erases the origin chain nor retroactively proves causal completeness. Broad learning lists, hybrid search, the Context Compiler, and mounted-reference context carry only a compact origin summary; explicit learning inspection exposes the full bounded lineage with a separate 32-source disclosure cap and truthful omission metadata.

Replay derives trust, provenance, confidence, temporal validity, correction history, corroborating-session count, and current-source freshness. Every proposal starts review-required; only a user confirmation creates trusted memory. Agent disputes and source-hash changes return a lesson to the review inbox without erasing its history. Rejection and supersession are terminal, and replacement graphs are checked for missing targets and cycles.

Context Mount authority is stored separately from both project memory and the observation catalog. The private mount registry records only a stable mount ID, active project ID, source project ID, creation time, whether the user explicitly enabled bounded agent context, and—in schema v3—a bounded history of historical mount-ID → source-project-ID pairs for mounts that were agent-enabled; project/vault paths remain owned by the existing catalog/binding registries. `ley mount add/list/remove` is the local authorization surface. Legacy v1 mounts stay agent-disabled until explicitly re-added, while existing schema-v2 agent-enabled mounts are migrated into mount history before the next mutation. Unmount removes current reference authority but intentionally does not erase that mount/source relation, because later mount-specific or source-project egress restrictions may still need to constrain historical derivatives in the active project. `ley_compile_context` may resolve only currently agent-enabled mounts for direct reference use while holding the mount lock, revalidate source identity/binding, and search already-captured source memory. Specifications and active-project context are assembled first; mounted references use only the remaining shared result/token budget, retain mount/source provenance and an `untrusted-mounted-project-memory` boundary, and never change the active project/session write scope. Lower-precedence mounted historical Decision/Learning guidance is also withheld when it explicitly negates an admitted trusted/current active-project Learning on the same terms; the exclusion is `conflicting-memory` and carries the exact conflicting active-project entity IDs. This conservative rule does not suppress mounted direct source evidence and does not infer conflict from semantic similarity alone. Missing, identity-changed, unbound, or unavailable captured sources fail closed and remain diagnostic.

Reusable team/organization Knowledge Scopes extend that explicit reference model without creating ambient cross-project access. The owner-private `knowledge-scopes-v1.json` registry stores a stable `ksc_` ID, `team`/ `organization` kind, name, immutable bounded source-project IDs, explicit active-project attachments, and bounded historical scope/source ancestry; it stores no project or vault path. `ley scope create/list/attach/attached/detach` is the local authority surface and MCP has no scope-mutation route. Attached sources reuse the same captured-memory search/admission logic as the active project and Context Mounts. Shared-reference precedence remains active project → explicit Context Mounts → shared Knowledge Scopes, disclosed as `referencePrecedence: active-project-over-mounted-reference` plus `sharedKnowledgePrecedence: explicit-mount-over-shared-knowledge`. As with explicit mounts, lower-precedence shared historical Decision/Learning guidance is withheld when it deterministically negates an admitted trusted/current active-project Learning; shared exclusions carry the exact conflicting active entity IDs and `sharedKnowledgeCoverage.activeProjectConflicts`, while contradictory shared direct evidence remains visible. Shared references remain read-only `untrusted-shared-project-memory`, are deduplicated against higher-precedence explicit mounts/overlapping scopes, consume only remaining result/token budget, and never change active-project write scope. ADR 0052 defines the reusable authority and ADR 0075 defines this active-state conflict extension.

Reusable team/organization Policy Bundles are a distinct human-intent authority composed from an attached Knowledge Scope plus exact already-approved source Specifications. The owner-private `policy-bundles-v1.json` registry stores a stable `pbd_` ID, parent scope ID/kind/name, immutable bounded source project IDs + Specification IDs + approved content hashes, explicit active-project attachments, and bounded historical source ancestry; it stores no policy body or project/vault path. `ley policy-bundle create/list/attach/attached/status/detach` is the local authority surface, and MCP/hosts expose no bundle mutation route. The parent scope must be attached first, preventing a bundle from silently broadening cross-project scope. Context Compiler human-intent precedence is **active-project Specifications → attached Policy Bundle Specifications → historical memory**; conflicting bundled policy is excluded in favor of a current active-project Specification. Bundled policy output is labeled `human-intent` with `sourceBoundary: user-approved-policy-bundle-specification`, keeps bundle/scope/source/spec/hash provenance, and consumes the same bounded compiler budget. Context Pack Inspector schema v3 exposes that metadata, precedence, coverage, and exclusions while omitting policy bodies. ADR 0053 defines this slice.

The external-reference connector supports explicit public GitHub issues/pull requests plus text documentation pinned to a full commit SHA without turning the core retrieval plane into a generic network client. `ley connector add` accepts only strict canonical `https://github.com/OWNER/REPO/issues/N`, `/pull/N`, or `/blob/FULL_40_HEX_COMMIT/PATH` forms, records deterministic `ext_` authority in an owner-private registry, and performs no network request. Branch/tag document URLs are deliberately rejected. `ley connector refresh` is the separate explicit network action: `ley-github-connector` reparses the authorized source, derives only the fixed `api.github.com` issue/PR endpoint or `raw.githubusercontent.com` commit/path endpoint, disables redirects, accepts no authentication material, and hard-bounds responses before parsing. Documents must be bounded UTF-8 text with safe relative paths ending in `.md`, `.mdx`, `.txt`, `.rst`, or `.adoc`. `ley-core` validates, redacts, content-addresses, and stores the resulting bounded snapshot inside the existing per-project Agent Memory namespace. Stored connector reads remain `untrusted-external-reference` evidence with `liveSourceChecked: false`; there is no background refresh. MCP exposes only read-only `ley_external_connectors_list` and `ley_external_connector_get`, both over local stored state and both subject to project plus connector egress. No MCP connector mutation or network route exists. ADR 0049 defines the authority/network foundation; ADR 0050 adds immutable document semantics.

Agent-context egress is enforced before host/model return. Project policy is a whole-scope ceiling; Specification policy is checked before an approved note is opened or task-scored; mount and source-project policy are checked before reference search; every Knowledge Scope source inherits its source project's policy and is checked before shared-memory search; each Policy Bundle source checks both its source-project policy and its source-Specification policy before the policy note is opened; connector policy is checked before connector metadata/snapshots are returned. Restrictive Specification/mount/connector overrides remain OS-private authority even if the currently approved/mounted/configured scope later disappears, while detached Knowledge Scopes and Policy Bundles retain bounded stable source ancestry so later project/Specification restrictions still constrain derivatives. Because ordinary session/decision/problem records and many learnings cannot yet prove complete causal independence from every finer-grained source that may have influenced them, Ley uses a conservative non-laundering fallback: whenever a Specification, mount, historically agent-enabled source, historically attached Knowledge Scope source, historically attached Policy Bundle source project/Specification, or external connector is blocked for the configured target, the agent-facing compiler withholds session/decision/problem/learning candidates whose source independence is unproven. Direct captured revision/artifact/symbol/dependency evidence remains governed by the active project's own policy. `egressCoverage.historicalMemoryWithheld`, `withheldDerivedResults`, `blockedPolicyBundleSources`, and the other source-specific blocked counters disclose that ceiling. Broad historical MCP readers, lifecycle startup context, and reviewed runbook export apply the same fail-closed ancestry rule rather than allowing a blocked source to be recovered through old session or learning text.

Topic Dossiers are the first P1 derived-intelligence view. `compile_topic_dossier` / `ley_topic_dossier` build an on-demand, non-persistent topic projection over the same fixed-project captured evidence and structured memory. The dossier preserves stable evidence IDs/citations, current trusted learning roles, conflicts, revision applicability, important artifacts, supporting sessions, open tasks/problems/unresolved items, and recent verification. Session/revision search rows are treated as secondary under budget pressure because supporting-session identity and top-level revision freshness already represent those dimensions. The projection is source-fingerprinted, strictly token-bounded, reports truthful omissions, keeps `liveSourceChecked: false`, and writes no dossier cache. It uses the same historical-memory egress gate as broad session/learning readers, so a restricted source cannot be laundered through topic consolidation. Dossiers are navigation/progressive-disclosure views, never authority and never a substitute for task-specific Context Compiler admission.

Current Project State is the next P1 derived-intelligence view. `current_project_state` / `ley_project_state` build an on-demand, non-persistent project-status projection over the fixed project's captured snapshot, structured sessions, reviewed learnings, revision metadata, and—when the caller explicitly supplies the fixed project's registry view—compact Specification authority metadata. Schema v2 exposes exact current approved Specification ID/path/hash/time handles as `authoritativeSpecifications` with `authority: human-intent`, `sourceIncluded: false`, and `followupTool: ley_project_specifications`; changed/missing approvals move to `specificationAttention` and are not active human intent. Specification bodies, Acceptance criteria text, and Verification method text are intentionally not copied into this state projection. Working state comes only from active/paused sessions and their latest checkpoint; open tasks/problems/unresolved items are drawn only from that bounded continuation state. Recent decisions and verification may be returned for orientation, but decisions are explicitly labeled `historical-project-memory` with `currentStateProven: false` so recency cannot silently become authority. Reviewed current-trusted learnings are separated from review-required, contested, stale, and source-changed knowledge. Specification authority/revision metadata participates in the deterministic state fingerprint and bounded coverage without consuming the copied-text budget. The projection carries `revisionFreshness`, truthful coverage/omission counts, `liveSourceChecked: false`, and no persisted state cache. It uses the same historical-memory egress gate as resume/dossiers/session/learning readers.

Context Pack Inspector is the third P1 derived-intelligence view. Every finalized compiled context pack carries a logical `contextPackId` plus `createdAtUnixMs`. The ID is computed only after active-project Specifications, attached Policy Bundle Specifications, active-project admission, explicit Context Mounts, shared Knowledge Scope references, premise/revision diagnostics, and agent-egress filtering are finalized, and excludes the creation timestamp so unchanged logical pack content can be reproduced. `ley_context_pack_inspect` recompiles through the same agent-aware compiler path and returns a text-light manifest: stable IDs/citations, authority/admission and inclusion reasons, Specification/Policy-Bundle/reference/egress exclusions, conflicts/premise warnings/gaps, retrieval and revision signals, budget composition, coverage/omissions, explicit bundle/mount/scope/source attribution, and follow-up handles. Inspector schema v3 deliberately omits included active Specification bodies, Policy Bundle policy bodies, and active/mounted/shared reference bodies and persists no historical pack. If an expected pack ID no longer matches, the Inspector reports that mismatch and refuses to claim it reconstructed the older pack. The original compile call owns `createdAtUnixMs`; Inspector reports `recompiledAtUnixMs` for the current reconstruction.

Memory Health / Hygiene is the fourth P1 derived-intelligence view. `memory_health_report` / `ley_memory_health` build an on-demand, non-persistent advisory report over existing typed learning trust/freshness, structured-session lifecycle/latest-checkpoint state, Memory Compiler recovery backlog, and revision metadata. The report can surface review-required/contested/stale/source-changed/uncited learning state, conservative duplicate/same-subject learning overlap, conflicting trusted-current claims without choosing a winner, incomplete sessions, unresolved active working state, post-checkpoint unconsolidated turn evidence, and divergent latest-checkpoint session memory. Every signal is advisory; `destructiveActionsTaken` is always false and the first slice has no mutation path. Ley now retains version-bound caller-declared Procedure application observations with typed downstream outcomes, but Memory Health still cannot classify successful/failed reverification because faithful procedure execution, causation, and comparable operating conditions remain unproven. That stronger reverification signal, failed consolidation attempts, and chronically unhelpful retrievals therefore remain explicit `unsupportedSignals` rather than weak age/outcome heuristics. Recovery-health output exposes metadata/counts, not prompt/response bodies, and the whole report remains behind the historical-memory egress gate.

Agent Legibility is the fifth P1 derived-intelligence view. `compile_agent_legibility_map` / `ley_agent_legibility` build an on-demand, non-persistent, source-bound table of contents over the fixed project's captured artifacts/graph, bounded structured-session metadata, and current approved Specification registry metadata. The map points to captured architecture/design documents, important top-level directories, declared root `package.json` scripts, separately labeled observed historical commands, project-policy references, schema/migrations, graph-derived API candidates, observability references, active/paused current plan items, and approved Specification metadata. Every category preserves a transparent selection basis; path/name and conventional directory-role classifications are navigation heuristics, not authority. The map copies no source excerpts or Specification bodies, reports missing categories as explicit gaps, exposes `tableOfContentsNotScore: true` with no score field, applies explicit section/session/text bounds with truthful coverage, and carries a deterministic logical `mapFingerprint`. Minimal capture never falls back to live source to invent commands, `liveSourceChecked` remains false, and the MCP projection uses the same historical-memory egress gate as other broad derived historical readers.

Reviewed Runbooks / optional host Skill export are the sixth P1 capability. `compile_reviewed_runbook` / `ley runbook compile` build an on-demand, non-persistent Markdown runbook only from explicitly selected same-project learnings that are verified, trusted, current, and typed as a procedure, pitfall, or convention. The projection preserves source learning IDs/provenance/freshness, applies source and text bounds, keeps `authorityIncreasedThroughProjection: false` and `liveSourceChecked: false`, and derives deterministic source/runbook identities without copying evidence notes, session turn bodies, or machine paths. `ley runbook export-skill` is deliberately separate from MCP: it requires an exact previously reviewed runbook ID plus explicit host and egress target, recompiles before export, fails if source state changed, applies historical-memory egress policy, and returns a non-persisted/non-installed Skill artifact. Ley does not silently install host policy or let an agent self-promote remembered text into instructions.

Snapshot-bound verification evidence links are the seventh P1 capability. A structured checkpoint verification may include up to 20 `evidenceArtifactPaths` that already exist in the current approved captured snapshot. For text evidence, the session writer resolves those project-relative paths into immutable artifact citations carrying snapshot ID, SHA-256 content hash, and captured line range; it never falls back to the live filesystem or copies the cited body into the verification record. Text evidence-linked checkpoints use session event schema v4 while ordinary lifecycle checkpoints remain v1, preserving explicit ledger evolution and backward readability. `ley_session_get`, Current Project State, and Topic Dossiers retain those links when they expose historical verification. Session Context and Current Project State cap returned verification-evidence citations at 64 per projection and disclose omitted citations; Topic Dossiers remain bounded by their serialized token budget. A passed result plus citation is still historical evidence rather than authority or live-source proof, and `liveSourceChecked` remains false.

The second P2 capability extends that provenance model to bounded original image evidence without turning images into text. Full Evidence capture may retain signature-validated PNG/JPEG/WebP originals in the existing content-addressed artifact store. Minimal/Structured refuse pixel retention. Media citations add `mediaType` and use `startLine: 0` / `endLine: 0`; any checkpoint carrying such a citation is a schema-v6 event and rebuilds to `session-v6.json`. `ley_read_media_evidence` returns exact cited bytes as a native MCP image block under the active-project egress gate, with a 180,000-byte source cap plus the existing 256 KiB serialized-result ceiling. Desktop inspection uses the same exact snapshot/hash read and loads browse-mode bytes only on explicit user action. No OCR, visual redaction, captioning, image embeddings, or generated description is part of this slice, so original media remains distinct from any later model interpretation. See ADR 0051.

Branch/worktree visibility and retrieval controls are the eighth P1 capability. Ley reuses the existing P0 `RevisionResolver` rather than creating branch-specific projects or a second Git model. `ley_session_get` recomputes each returned checkpoint's `revisionApplicability` against bounded current local Git metadata and returns top-level `revisionFreshness`; fixed-project Memory Search optionally filters exact `current-lineage`, `ancestor`, `merged`, `divergent`, or `unknown` applicability before conflict/ranking/result packing. Omitting the filter preserves all-history search. `collectedCandidates` remains the pre-filter bounded count while `revisionFilteredCandidates` discloses deliberate scope removal. CLI, MCP, Tauri, and desktop expose the same vocabulary, and the desktop shows captured revision beside current applicability/current Git metadata. A branch can therefore move from divergent to merged at read time without re-ingestion. Compatibility is applicability metadata only: it grants no trust/authority, cannot bypass egress/compiler admission, and never makes `liveSourceChecked` true.

Captured relative-import graph resolution is the ninth P1 capability. Ley strengthens the existing captured project graph rather than introducing a second dependency engine: unambiguous relative JavaScript/TypeScript import specifiers can resolve to captured file nodes, producing deterministic `imports` relations with captured-source citations. Package imports, ambiguous matches, and paths that escape the captured project stay unresolved/external instead of being guessed. `ley_graph_neighbors` and `ley_graph_path` can therefore answer bounded structural-impact questions such as which captured test imports a changed implementation, while direct Context Search remains the simpler lexical baseline. These graph relations are captured evidence only, never authority or proof that the live workspace still matches; `liveSourceChecked` remains false.

Bound context/memory utility feedback is the tenth P1 capability. It uses a two-phase write-enabled MCP protocol instead of trying to reconstruct historical packs after work has changed session state. Immediately after `ley_compile_context`, `ley_context_utility_bind` recompiles through the same egress-aware compiler path and persists only bounded metadata for the exact logical `contextPackId`: a `cub_` binding, redacted task excerpt, snapshot IDs, compile limits/token estimate, and stable included-record handles. Active-project learning handles also retain the exact learning kind/event count supplied by that pack; no learning/context body is copied. Later, `ley_context_utility_observe` can cite only checkpoint/session-finish events from the same session whose immutable sequence is after that binding; Ley derives typed task/problem/attempt/verification/terminal outcome counts under the session lock. Ordinary bind/observe events remain session schema v5. An observation may additionally carry bounded caller-declared `claimedAppliedLearningIds`; each ID must be the exact active-project Procedure/version present in the immutable binding, and such claim-bearing observations use schema v15. `ley_session_get` joins recent observations back to their bindings, while `ley_learning_get` derives a bounded reverse history with bound learning event count, task excerpt, typed outcomes, and explicit version-match state. Procedure application remains a claim rather than proof: `procedureFollowedProven`, `conditionApplicabilityProven`, `contextUsageProven`, `causalUtilityProven`, `trustChangesApplied`, and `rankingChangesApplied` remain false. No automatic trust promotion/downgrade, retrieval boost, utility score, hidden analytics service, or new desktop dashboard is introduced; see ADR 0073.

The desktop Agent Memory workspace is a thin Tauri adapter over these shared core projections. Its first level is a bounded, recent-first Projects hub derived only from the private observation catalog. Each card revalidates the live project identity and independently reports ready, unbound, uncaptured, missing-project, moved-vault, identity-change, or memory-error state; ready summaries read counts only from that project's resolved vault, and exact session-state totals stream over records without retaining every session projection. A separate bounded cross-project search independently revalidates every observed project and searches sessions, decisions, problems/outcomes, lessons, captured files, symbols, and dependencies through captured projections; unavailable scopes are counted and skipped, results remain cited and untrusted, and the worker never scans for or silently captures projects. Opening a project leads to its overview, Sessions, Decisions, Problems & Outcomes, Lessons, Specifications, Artifacts, graph, and Review surfaces. Initialization uses Structured capture, binding uses the private registry, and refresh runs deterministic ingestion. The graph can reopen any indexed immutable capture, applies type/relationship/provenance filters in the shared engine before bounding, and reads a selected node or edge citation only from that capture's matching immutable artifact. Session/activity evidence navigation uses a separate snapshot-pinned read: the engine requires the recorded artifact snapshot, path, content hash, and bounded line range, rejects mismatched hashes, and never falls back to the live working tree. Minimal captures report that source was not retained. The overview consumes a token-bounded resume pack, while Sessions reads a separate complete lightweight index so a bounded context pack is never mislabeled as full history. Opening a session replays a bounded context projection with checkpoint decisions, tasks, problem attempts/outcomes, structured resolutions, commands, verification, handoff, snapshot-pinned artifacts, and the newest naming revisions; original names and omission counts remain visible. Cited artifact controls open the exact historical excerpt beside its captured graph context, while learning evidence links to its complete originating session and artifact inventory. The user can append a reasoned rename even after completion without changing session identity. The learning provenance inspector shows temporal validity and immutable history. Its correction editor preserves the complete authoritative evidence set, appends a user-authored version, and resets trust; correction and review actions carry the inspected event count so a concurrent event fails stale instead of approving unseen text. Separate explicit note-link paths copy either a fully visible current trusted lesson or an inspected bounded session handoff into ordinary Markdown with portable provenance. Before either action, the native adapter canonically matches the open notes vault to the project's private binding; cross-vault writes fail without exposing machine paths. Linked notes enter the normal vault/index/navigation path while their source ledgers remain immutable and independent; stable learning or project/session IDs prevent duplicate promotion after note renames or moves. The PWA renders an explicit capability boundary because browser vaults cannot expose the OS-private catalogs or stdio MCP process.

Capture & privacy settings are loaded only when their project surface opens. The shared engine serializes privacy writers with a project-specific lock in Ley's private OS configuration, revalidates project identity and the expected current mode under that lock, and atomically changes the repository-local evidence policy. It preserves custom roots/ignore/limit fields and requires explicit consent before enabling raw-evidence permission. The native adapter then re-ingests through the existing bound vault and returns a refreshed dashboard. Minimal omits current source blobs; Structured retains redacted UTF-8 source but excludes original image pixels; Full Evidence additionally retains supported PNG/JPEG/WebP originals and permits compatible adapters to submit raw host evidence, while still not capturing transcripts automatically.

Whole-project Agent Memory erasure uses a distinct lifecycle lock stored beside, rather than inside, the erasable project namespace. Every artifact/graph, session, and learning store holds that lock shared for the duration of an operation; deletion holds it exclusively, revalidates the project-relative no-follow directory, and removes the complete namespace. Project source, ordinary vault content, `.ley` metadata, binding, observation, and the content-free lifecycle lock remain. The resulting inspection state is **Needs capture**. This is logical local deletion and makes no forensic-wipe claim.

MCP session writes are absent by default. `--allow-session-writes` enables start, generic checkpoint, finish, the narrow bound unresolved-recovery commit route, the schema-v8 minimal Decision/Problem commit route, the schema-v9 typed Task commit route, the schema-v10 typed Plan commit route, the schema-v11 atomic multi-claim commit route, the schema-v12 rich-Problem commit route, the schema-v13 rich-Problem composite commit route, and the explicit context-utility bind/observe workflow at process construction, so an existing read-only configuration cannot gain authority from a tool argument or stored instruction. The generic, typed Plan/Task, batch, rich-Problem, and composite verifiers remain read-only. Utility binding must happen before the measured downstream work; outcome observation may occur after terminal finish as a narrow evidence-only exception. Write tools return compact receipts and delegate to the same session engine as the CLI.

MCP learning proposals use an independent startup capability. `--allow-learning-proposals` adds one route that hardcodes agent authority and produces only tentative, review-required records. Confirmation, correction, rejection, supersession, deletion, and promotion remain absent. Default lesson listing includes only user-trusted records whose artifact citations still match the latest captured snapshot; explicit review/all scopes remain visibly untrusted.

The lifecycle adapter is a separate stdout-clean CLI surface. `ley hook --host ...` accepts the current host's documented JSON event, ignores transcript paths, and maps the host/session pair to a deterministic project-scoped Ley session in normal initialized-project mode. Agent-facing hooks use the same OS-private egress authority as MCP: the default target is `cloud`, and `--egress-target local` is an explicit integration assertion rather than runtime attestation. A project-level denial produces a host-valid no-op without creating/capturing a Ley session. When a finer-grained source blocks historical egress, SessionStart may establish only the stable Ley session identity and injects a content-free egress-withheld notice; it does not read or inject the resume pack, reviewed learnings, or recovery state. When allowed, startup uses the existing bounded resume projection. `UserPromptSubmit` then appends bounded turn evidence and, for an exact task representable by the compiler's existing query bound, runs the same Specification/mount/scope/policy/egress-aware Context Compiler and injects a compact non-persistent task projection. The host renderer does not repeat the raw prompt, keeps a strict output bound, exposes its own omissions, creates no utility binding/write authority, and falls back without truncating an oversized or otherwise unavailable task query. Exact delivery retries keep capture idempotent and simply recompile current context. Prompt/response bodies never enter SessionStart context. If the same resumed session has post-checkpoint observations, startup injects only a bounded recovery count/state signal; explicit `ley_session_memory_compile` inspection followed by the matching single-candidate verifier or the atomic batch verifier is required before reconstructing evidence-derived structure. Ordinary uninitialized and unbound working directories remain explicit no-ops, and payload paths never select the project. ADR 0058 defines the prompt-time uninitialized exception: a workspace with explicit Bootstrap Specification authority keeps SessionStart/Stop as no-ops but may receive a whole-Specification `UserPromptSubmit` projection with no Ley session or turn capture. ADR 0059 adds explicit Bootstrap Reference authority to the same one-tool MCP mode, but reference-only authority remains a lifecycle-hook no-op. Rich structured memory still comes from typed MCP checkpoints after normal project initialization. ADR 0057 defines the normal prompt-time compiler projection; ADRs 0058/0059 define bootstrap behavior.

Project resume context composes these existing stores without creating a new authority layer. It prioritizes active and paused sessions before recent history, projects only the newest checkpoint and handoff details needed to continue, and includes only verified/trusted/current artifact-backed lessons. Stable IDs link every compact item back to the bounded session, learning, graph, or artifact readers. Both CLI and MCP use the same projection and budget rules.

## Persistence contract

For filesystem vaults, Markdown is authoritative. A vault scan projects files into Dexie, then rebuilds links and tags after every page exists so forward references resolve correctly. First scans derive IDs from vault identity and relative path; subsequent scans preserve the current ID for each matching path so in-session creations, renames, tabs, and revisions remain coherent.

The active `pages`, `assets`, and `revisions` tables represent exactly one vault at a time. Before a browser-local vault yields the active projection to a filesystem folder, Ley snapshots its authoritative pages, binary assets, and revision history into dedicated browser-local tables. Returning restores that snapshot and rebuilds disposable links/tags. Filesystem rescans preserve existing IDs by path for the same vault, while changing vaults clears cache-only assets and history so state cannot leak across vault boundaries.

Writes follow this order:

1. Serialize YAML properties and Markdown body.
2. Persist the file through the active vault adapter. Desktop writes stage and atomically rename a temporary file.
3. Update the local page projection.
4. Rebuild backlinks, tags, search, and graph-derived state.

Editor content writes are serialized per note. A rapid later save cannot be overtaken by an earlier filesystem/index rebuild, and leaving an editor flushes its pending debounced value before teardown. This keeps authoritative Markdown and every derived row on the same newest revision.

Cell-level property mutations also join the per-note mutation queue and merge against the newest projected frontmatter inside that queue. Two collection cells, the properties panel, and an editor autosave therefore cannot overwrite one another with stale object snapshots.

Renames move the file and retarget incoming wiki links. Ordinary relative Markdown links are resolved by vault path, indexed as backlinks and graph edges, and rewritten when either their source or target moves so their filesystem meaning remains stable. Folder moves preserve note identity and titles, so links and note bookmarks remain valid; duplicates receive an independent title/path and intentionally drop aliases to avoid ambiguous resolution. Deletes move filesystem notes into `.trash`; browser-local notes use a recoverable soft-delete marker and expose restore/permanent-delete controls. Binary attachments live under `attachments/` and are constrained by extension, size, and safe relative paths. Interoperable JSON Canvas documents live under `canvases/` and use the same atomic-write and trash lifecycle. Ley normalizes all JSON Canvas 1.0 text, file, link, and group nodes plus file subpaths, group background metadata, colors, edge sides, endpoint styles, and labels; malformed geometry and dangling edges are excluded before rendering or saving. Spatial edge paths are derived from document coordinates so resize, pan, zoom, reload, and cross-app imports do not depend on transient renderer measurements. All native relative paths reject absolute paths and traversal segments.

Workspace metadata is namespaced by the active vault identity. Desktop vaults use their full path, browser-local uses a dedicated identity, and browser directory handles receive a persisted random ID rather than relying on a potentially colliding folder name. Note bookmarks, destination bookmarks, saved searches, named workspace layouts, and navigation sessions therefore never cross vault boundaries. Saved searches are validated setting records rather than hidden note files, because they describe Ley workspace retrieval rather than user-authored knowledge. Their optional collection configuration contains presentation-only column IDs and sort direction; every displayed value is still read from Markdown/YAML. Heading and block bookmarks resolve a note by stable page ID and then path; heading text and explicit `^block-id` anchors provide the durable in-note destination. Creating a block bookmark writes that portable identity into authoritative Markdown instead of storing a fragile line offset. Missing-note bookmarks remain visible and recover automatically if the note returns. Navigation sessions store both stable page IDs and paths, restore tab order, primary and secondary panes, focused pane, and recents, and discard references to deleted or unavailable notes. Named layouts reuse that resilient note-reference contract and add presentation-only sidebar visibility, right-dock context, and split width; loading drops missing notes and refuses to replace the live arrangement when every reference is stale. Editor insert/jump events carry their page identity, and link opens carry their source pane, so two mounted editors cannot receive one another's commands.

The desktop runtime owns one recursive native watcher for the active vault. It emits only visible Markdown and JSON Canvas paths, ignores hidden/internal files, and suppresses events caused by Ley's own atomic writes. The web layer debounces event bursts before rescanning and reconciles tabs against the new projection. If an external edit arrives while the current CodeMirror document is dirty, autosave pauses and the user explicitly chooses the disk version or their local version; neither side wins silently.

## Derived state

Dexie tables for pages, blocks, links, tags, and settings support reactive UI queries. FlexSearch and the synchronous title resolver subscribe to Dexie and are disposable. CodeMirror's shared completion lifecycle reads the derived tag table on demand, so tag authoring reuses the current vault taxonomy without making the index authoritative. The search projection indexes title, aliases, content, tags, paths, and flattened YAML properties; structured operators are parsed separately and applied as composable post-filters so filter-only queries and exclusions remain exact. Collection tables reuse the same parsed filters against a live page/tag snapshot, discover columns from frontmatter coverage, and never persist row data outside the notes. Revisions are sparse checkpoints rather than keystroke logs and are restored through the same normal save path.

## Design system

Ley uses self-hosted Geist Sans and Geist Mono with semantic CSS tokens. Radix primitives provide accessible interaction foundations where native controls are insufficient. Feature components consume shared buttons, inputs, keyboard hints, and tokens rather than hard-coded brand values.

## Non-goals

- A proprietary document format
- Mandatory cloud accounts or sync
- Treating the graph as the primary editor
- Claiming browser-local storage is equivalent to a filesystem vault
- A plugin API before the core file format and lifecycle are stable
