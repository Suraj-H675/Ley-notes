# Ley verification map

These recipes cover the implemented transition runtime. Read `docs/runtime-verification.md` for the broader release contract and `LEY.md` for future milestones. Do not substitute planned Overview/Knowledge/History/Review navigation for the current Continue/Recall/Evidence/Review/Project settings controls.

## Preconditions and conventions

Launch and doctor through the parent skill. The CLI fixture contains `README.md` with `verificationbeacon`; ingestion creates native private continuity without a vault. Each invocation records a public command and its output. The helper's `drive` runs the four CLI recipes in order. A native run uses separate state and follows each file's Desktop entry points, with fresh accessibility tokens and before/action/after evidence.

Report each entry point as passed, failed, or blocked. An absent host, inaccessible window, or missing native prerequisite is blocked. CLI engine proof does not prove the corresponding Desktop interaction. Brief/evidence has no CLI-helper claim. Cua Driver's initial preflight in this environment reported an unreachable AT-SPI bus, so native paths remain unverified until that prerequisite is available.
